# Chrome Popup 选择配置文件后导入未保存

- 日期：2026-11-06
- 范围：CookieSync 设置 → 导入配置（不是 Cookie JSON 导入）
- 环境：macOS 27.0；Chrome 156.0.8078.81；独立 Chrome for Testing 156.0.8078.80、156.0.8078.73
- 状态：暂缓进一步修改，保留 1.6.3 独立导入窗口交互；具体浏览器回归原因未确认。

## 现象

用户报告选取有效配置文件后，工具栏 Popup 关闭且配置未生效。用户最后确认插件 1.5.3 正常导入的日期为 11 月 3 日，之后升级插件仍出现异常。

## 证据

### 插件代码

- 1.5.3（fe68466）至 1.6.1（8a4ac81）：`importConfigFile`、`setupShareActions`、`fillEditor`、`setupEditor` 内容完全一致；`chrome/form-cache.js`、`chrome/service_worker.js` 文件完全一致。
- 1.6.2 的 0b6a846 修改配置消息保存链路，处理长连接断开及保存确认；1.6.3 的 e823a2e 改为后台创建独立导入窗口。两者均为问题报告后的处理。
- 完整原版 1.5.3 也能复现异常，因此新增 Cookie 管理功能不是复现所必需。

### 浏览器更新

本机 GoogleUpdater 日志显示成功安装更新：11 月 3 日 `.79 → .80`，11 月 4 日 `.80 → .81`。安装时间不等于浏览器进程实际切换版本的时间，不能据此确定用户最后成功时运行的版本。

Chromium 官方公开提交中，`.79 → .80 → .81` 均仅修改 `chrome/VERSION`。未找到这些补丁版本修改文件选择逻辑的源码证据；这不能排除发行构建、实验配置、系统环境或时序因素。

### 实际运行对照

均使用原版插件 1.5.3。测试配置为无敏感信息、带可识别标记的 JSON。

| 浏览器 / 页面 | 观察结果 | 保存验证 |
| --- | --- | --- |
| 正式 Chrome .81 / Popup | 自动化选择原文件后关闭 | 当时已有配置与目标相同，单凭字段不能确认写入；用户另报告手动操作关闭且不生效 |
| 独立 Chrome for Testing .80 / Popup | 选择测试文件后关闭 | 再次打开仍为默认配置，确认未保存 |
| 同一 .80 / 将 popup.html 打开为普通标签页 | 导入成功 | 刷新后仍保留测试值 |
| Chrome for Testing .73 / Popup，第一次 | 保持打开，字段更新 | 关闭再打开仍保留第一份测试值 |
| 同一 .73 / Popup，第二次 | 选择后关闭 | 再次打开显示第二份测试值，确认保存成功 |

`.73` 测试复用了 `.80` 的隔离测试配置目录，未使用日常 Chrome 的个人配置。测试启动时曾观察到字段和导入入口初始化延迟，等待后恢复。原生 UI 自动化的焦点与时序影响尚未排除。

## 原因与未决项

已验证：相同旧版代码在持久页面可正常解析并保存文件，异常集中于工具栏 Popup 与原生文件选择交互；Popup 关闭并不必然意味着导入失败。

尚未确认：是否为稳定的 Chrome 版本回归、具体引入版本或 Chromium 提交。`.73` 两次成功与 `.80` 失败构成版本相关线索，样本量和控制变量不足以认定根因。

## 当前处理

按用户决定，不继续调整交互，保留 1.6.3：设置 → 导入配置 → 独立导入窗口 → 选择文件。由持久窗口处理读取和反馈，后台确认配置保存。

撤回本次未提交的 `showOpenFilePicker` 直接导入、fallback 按钮及对应 README 和测试实验改动。工作区恢复到 e823a2e 的实现；本机正式插件恢复为 1.6.3。没有发布新的功能修复。

## 后续复现要点

如恢复排查，应固定插件代码、系统、浏览器测试配置及测试文件，用不同标记配置重复交叉测试 `.73` 与 `.80/.81`；每次关闭并重新打开检查持久值。增加无自动化干扰的手动对照，不以 Popup 是否关闭单独判断成功，也不以标签页成功代替工具栏 Popup 验证。
